# Agent 日常使用指南

本页帮助 Hermes Agent 或其他助手从工作空间接收任务并找到实际操作位置。协作约定以 [AGENTS.md](../AGENTS.md) 为入口，仓库选择见 [仓库索引](repositories.md)。这里提供文件与任务约定；尚未配置或验证 Hermes 的自动加载、工具权限和运行环境。

## 首次交接

可向助手提供以下启动说明，工作空间路径按实际机器调整：

> 使用 my-workspace 作为我的个人工作入口。先阅读根目录 AGENTS.md 和 README.md，再按任务查看 docs/repositories.md、config/repos.json 及存在时的 config/repos.local.json。进入目标仓库后读取其自身约定。查询、整理和修改按我的任务直接开展；保留已有改动，只处理本次相关内容。完成后给出文件位置、验证结果和 Git 状态。

先运行 `python3 scripts/repos.py list` 获取登记信息。需要检查本地是否具备相关仓库时运行 `python3 scripts/repos.py status`，或直接检查目标目录。缺失仓库可按任务需要用 `python3 scripts/repos.py clone <name>` 克隆；已有路径会跳过，需自行核实是否为正确仓库。访问失败应说明实际缺失内容。

## 查询资料

先确定主题与可能的内容归属，读取相应索引，再用 `rg` 搜索目标目录。例如查询日常收录中的 Agent 资料：

```bash
rg -n -i 'hermes|agent' repos/notes/my-daily-remarks/notes repos/notes/my-daily-remarks/summaries
```

对命中的正文按需阅读；跨仓库问题再扩展到相关项目或笔记库。回复保留来源路径、资料日期和结论依据。找不到时说明搜索范围；涉及“最新进展”时核查近期文件和必要的实时来源，不能把索引中的简介当作实时状态。

## 修改或添加内容

1. 按任务选择落点；读取目标 README、适用的协作约定、模板和邻近内容，检查该仓库的 `git status --short --branch`。
2. 搜索是否已有相同主题或来源；优先补充已有记录，避免重复正文。只有关键归属或目标不清楚时询问。
3. 按现有结构写入，更新必要索引和相关链接。保留来源、日期；区分事实、分析、待核实内容及用户表达过的观点。
4. 检查本次 diff、路径和链接。代码或站点改动按目标仓库要求验证；普通笔记检查内容与索引即可。
5. 交付实际文件路径、变更摘要及验证范围；需要后续行动时写清下一步。

“收录这篇文章”通常表示在 my-daily-remarks 创建记录并更新月索引；“整理成公开文章”表示在 my-ai-observe-notes 准备发布稿。收录日期与来源发布日期分别记录；不知道发布日期时不猜测。“我的提炼”若缺少用户观点，可标注为“Agent 初步提炼，待本人确认”，不要替用户表达认同。

公开稿从收录或私人材料整理而来时，保留必要来源并去除私人信息。my-ai-observe-notes 当前工作流会在推送 main 后构建并部署 GitHub Pages，因此向该分支推送公开稿同时会触发发布；执行前说明这一实际效果，并按当前任务授权处理。

## 内容归档与后续任务

工作记录写入 journal/，可包含已完成内容、关键结论和下一步；持续任务写入 plans/ 或对应项目已有的追踪文件。每次接续先读必要的近期记录，以当前文件和实际状态校验旧结论。无需把每段对话或每个短任务都落盘，也不要在多个仓库重复维护同一正文；跨仓库通过相对路径或来源链接关联。

## Git 与同步

父仓库和每个子仓库分别检查、提交和同步。父仓库忽略 repos/，其干净状态不能证明子仓库没有改动。不要对所有仓库批量提交或推送，也不要固定假设分支名是 main。

用户要求推送时，按当前任务确定涉及的仓库，审查相关改动，仅暂存本次明确路径，核实远端和分支后执行。远端领先时可在工作树和历史允许的情况下快进同步；遇到分叉、冲突或已有改动阻碍同步时，保留现场并处理具体问题，不强推或重置。

工作空间清单只保存无凭证地址。本地清单、忽略目录和私人正文不会随父仓库备份，完整恢复仍依赖对应仓库及单独备份。新增仓库流程见 [使用与维护](workspace-guide.md#纳入一个仓库)。
